## 2. 判断が必要（ユーザーが決めるまで着手禁止）

### D-1 OpenAI プロバイダ経路を削除するか [読解]

**現状:** `services/anthropic_client.py:78` `_is_openai()` 以下、`generate_text` / `stream_text` / `stream_text_with_thinking` / `stream_chat` / `stream_chat_with_tools` に OpenAI 分岐が約 80 行ある。しかし:
- `generate_json()` は prefill + `stop_sequences` 前提だが OpenAI 分岐は `stop_sequences` を渡さない → クエリ分解・ギャップ検出・スコア抽出・引用検証・Consensus Meter が **OpenAI モデルでは全部壊れる**
- `record_anthropic()` が呼ばれないので使用量が記録されない
- vision・PDF・tool use・document_qa・web_search は Anthropic 専用（`ValueError` か API エラー）
- リポジトリ `CLAUDE.md` は「No LangChain — use Anthropic SDK directly」
- `requirements.txt:4` の `openai>=1.50.0` は唯一の floating pin

**推奨:** 削除。`anthropic_client.py` の分岐、`routers/settings.py:28` `STATIC_OPENAI_MODELS`、フロント `settings/page.tsx` の OpenAI キー欄、`requirements.txt` の `openai` を落とす。**`model_settings.openai_api_key` カラムは残す**（既存 DB との互換、マイグレーション不要）。
**やらない場合:** T-06 の `model` 許可リストで `gpt-*` を拒否するだけにする。

### D-2 `/api/digest/send-now` を admin 限定にするか [読解]

**現状:** `routers/digest.py:152` は `quota_guard` のみで `require_admin` なし。member が押すと Tavily 検索 + Claude 見出し生成 + **管理者が設定した宛先へのメール送信**が走る。同じファイルの PUT は admin 限定になっている（docstring で「member が保存すると全体に波及する」と書いてあるのに send-now は素通り）。
**推奨:** `Depends(require_admin)` を追加し、フロント `digest/page.tsx` の Send Now ボタンを `isAdmin` で隠す。
**論点:** member にテスト送信させたい運用があるなら quota だけで許容という判断もある。

### D-3 `max_sources` などの上限値 [読解]

`schemas/research.py:8` `max_sources: int = 5` に上限がない。API を直接叩けば `max_sources=500` を送れ、Tavily 検索と要約呼び出しが比例して増える（費用）。フロントは 5/8/12 のみ。
**推奨:** `max_sources` 1〜20、`top_k` 1〜20、list の `limit` 1〜100、自由文（`query` / `topic` / `question` / `custom_instructions` / `custom_system` / `context`）は 20,000 文字。**値は決めてもらう**（T-06 はこの値で実装する）。

### D-4 draft workspace の永続化先 [本番未確認]

`services/text_editor_tool.py:31` の `WORKSPACE_DIR` はコードの隣（`backend/workspace/`）。Render ではコードディレクトリはデプロイ毎に消えるので、**チャットで作った下書きはデプロイのたびに消える**（BM25 索引が消えていたのと同じクラス）。
**推奨:** `config.py` に `workspace_dir: str = "./data/workspace"` を追加し、`render.yaml` と Render ダッシュボードに `WORKSPACE_DIR=/data/workspace` を足す（T-13）。
**論点:** 下書きを「一時的なもの」と割り切るなら現状維持でもよい。§6 (c) で本番のパスを先に確認。

### D-5 MCP ブリッジを本番で無効化するか [本番未確認]

`.mcp.json:5` は `cd backend && exec ./venv/bin/python mcp_server.py` を起動する。Render には `backend/venv` が存在しない（`render.yaml` の buildCommand は素の `pip install`）ので、**チャット 1 ターンごとに bash を spawn → 失敗 → stderr にログ → キャッシュされず次ターンも再試行**（`services/mcp_bridge.py:148` の「全滅ならキャッシュしない」設計のため）。仮に起動できても `mcp_bridge.py:226` は `DATABASE_URL` 等を子プロセスに渡さないので、子は `./data/research.db` という**空の別 DB** を作って「文書なし」を返す。
**推奨:** `config.py` に `mcp_bridge_enabled: bool = False` を足し、`get_mcp_tool_defs()` 先頭で `[]` を返す。ローカルは `.env` で `true`。あわせて子プロセスに `DATABASE_URL` / `CHROMA_PERSIST_DIR` / `BM25_INDEX_PATH` / `UPLOADS_DIR` を明示的に渡し、`.mcp.json` は `sys.executable` を使う形に変える（T-14）。
**論点:** 本番でも MCP ツールを使わせたいなら「渡す env を増やす」方向。§6 (b) で本番ログを先に確認。

### T-01 PDF エクスポートが本番で 500 になる
- 重要度: **High** / 検証: **[実測]** / 担当: **Sonnet**
- 場所: `backend/utils/pdf_renderer.py:9`（`_JP_FONT = "/System/Library/Fonts/ヒラギノ角ゴシック W3.ttc"`）、`:29`（`font = "Helvetica"` フォールバック）
- 現象: macOS 専用フォントが無い環境（Render = Linux）では fpdf2 のコアフォント Helvetica に落ちる。fpdf2 のコアフォントは latin-1 しか書けず、`—`（U+2014）ですら `FPDFUnicodeEncodingException` を投げる。venv で実測:
  ```
  'a → b'  RAISES FPDFUnicodeEncodingException
  'x ≥ 3'  RAISES
  'em — dash' RAISES      ← Claude の出力にはほぼ必ず含まれる
  '日本語'  RAISES
  ```
  つまり `GET /api/reports/{id}/export?format=pdf` と `GET /api/analysis/{id}/export?format=pdf` は本番でほぼ常に 500。
- 変更:
  1. `backend/assets/fonts/DejaVuSans.ttf` と `DejaVuSans-Bold.ttf` をリポジトリに追加（DejaVu は自由ライセンス、合計 約 1.4 MB。ライセンスファイル `LICENSE-DejaVu.txt` も同梱）
  2. `make_pdf()` を「DejaVu を**無条件に**登録、Hiragino があればそれを優先」に変える。`Helvetica` フォールバックは削除
  3. `pdf.add_font("DejaVu", "", path)` / `add_font("DejaVu", "B", bold_path)`
- 触らない: `render_markdown` / `_write_inline` のロジック、`utils/export.py`
- 検証:
  ```bash
  cd backend && ./venv/bin/python -c "
  from utils.export import render_pdf
  b = render_pdf('Title — with dash', 'x ≥ 3 → ok\n\n- 日本語 bullet')
  assert b[:4] == b'%PDF', b[:20]; print('ok', len(b))"
  ```
  これに加えて `tests/test_export.py` と全ランナー。**フォントを一時的に隠して**（`_JP_FONT` をダミーパスにして）同じコマンドが通ることを確認する — Hiragino のある Mac で通っただけでは本番の再現になっていない。

### T-08 ログイン制限が X-Forwarded-For の先頭で鍵付けされている
- 重要度: **High（本番で成立すれば）** / 検証: **[本番未確認]** / 担当: **Opus** / **前提: §6 (a) の結果**

- 現象: リバースプロキシは通常 XFF を**末尾に追記**するので、先頭はクライアントが自由に書ける。攻撃者はリクエストごとに XFF を変えるだけで 5 回/5 分の制限を無限に迂回できる。監査ログの `ip_address` も汚染される。
- 変更（§6 (a) で「先頭が偽装値になる」と確認できた場合）:
